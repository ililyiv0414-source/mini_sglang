# 固定位置 CUDA Graph 原型

来源：artifacts/decode-graph-fixed.json。A800、BF16、batch=1、原始 PyTorch RMSNorm；每样本重复调用 30 次，普通执行与 graph replay 交替五轮。固定历史和缓存写入位置，无自回归推进。

| 历史长度 | 普通执行中位数 ms/调用 | Replay 中位数 ms/调用 | 加速比 | 捕获耗时 ms |
| --- | ---: | ---: | ---: | ---: |
| 512 | 19.124 | 5.433 | 3.520× | 97.220 |
| 1024 | 18.922 | 5.817 | 3.253× | 69.520 |

每个长度验证三个不同输入 token 并重复第一个 token：logits 和 argmax 与普通执行完全一致，历史 K/V 未被修改。五轮耗时范围：512 eager 19.077–19.234 ms、graph 5.413–5.444 ms；1024 eager 18.906–18.988 ms、graph 5.816–5.822 ms。

结论：在固定位置原型中，降低重复 host 派发带来明显收益，支持推进动态位置解码研究。不是线上吞吐，也不是完整自回归生成加速比。

计时排除 token 更新、prefill、分配、预热及捕获。Graph enqueue 约 15–22 µs/调用，但 GPU 完成需约 5–6 ms；不能将 enqueue 速度当作 token 生成速度。捕获前后 allocated 增量约 8.42 MiB（512）和 0.29 MiB（1024），这些只是当前进程采样差值；reserved 在捕获后下降，受分配器回收影响，不能据此声称 Graph 降低显存。

下一阶段必须处理：设备端位置与有效长度更新、固定地址的 KV 写入、attention 有效范围、token 回馈、EOS/长度上限、重置与跨请求隔离。以新的动态路径逐步正确性验证和完整生成计时作为验收，不外推本原型的 3.25–3.52×。
