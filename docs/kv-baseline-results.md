# 连续 KV Cache 首轮性能实验

数据：artifacts/benchmark-kv-fixed.json。A800 80GB，共享 GPU；Qwen3-0.6B，BF16，batch=1，固定 32 个预测位置，31 次 decode。合成 token 回放，每个长度预热一次、交替顺序测量三次，以下为中位数。

| 输入长度 | 重算 decode ms | 缓存 decode ms | decode 加速比 |
| --- | ---: | ---: | ---: |
| 128 | 591.833 | 588.091 | 1.006× |
| 512 | 584.382 | 589.053 | 0.992× |
| 1024 | 1313.467 | 586.757 | 2.239× |

正确性：各长度、各路径所有回放步骤 logits 与对应 Transformers eager 路径完全一致；所有计时轮次预测 token 与各自参考结果一致。此前 BF16 自由生成分歧也在 Transformers 中复现；FP32 固定同一历史诊断中没有 argmax 分歧。FP32 与 BF16 诊断各自采用自身完整重算结果推进历史，不能将全程误差比较理解为完全相同的跨精度输入轨迹。

1024 长度时总执行时间从 1343.974 ms 降至 617.675 ms（约 2.176×）。重算与缓存的 peak allocated 分别为 1626582016 与 1732694016 字节；缓存预分配 120995840 字节。峰值包含 prefill、权重和临时张量，不等同于 decode 显存，也不等同于 KV Cache 容量。

边界：排除模型加载、token 缓冲及缓存分配时间；计入 Python、算子派发和 argmax；每次 forward 都计算所有输入位置的 logits，重算路径存在可优化的冗余 LM head 工作。不是线上服务吞吐，不是与 SGLang/vLLM 的速度比较。仅三轮、共享硬件，不作显著性或普遍收益断言。

观察：缓存 decode 在三个长度下都约 587–589 ms，即每步约 19 ms。短上下文没有明确加速，长上下文收益明显。CPU 派发/大量小算子可能构成短序列瓶颈，但尚无 profiler 证据，不应作为确定结论。下一步先分别采集 CPU/CUDA timeline，再选择末位置 LM head、算子融合或 CUDA Graph 等优化。
