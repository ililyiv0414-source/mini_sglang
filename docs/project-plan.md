# 项目设计与实验协议

## 背景与目标

自回归推理的 prefill 与 decode 具有不同执行特征。不同长度请求共同服务时，固定批次可能造成等待与空闲；KV Cache 的分配方式会影响显存占用和可承载并发。以上是待测假设，不作为已经观察到的瓶颈。

第一版聚焦单卡、单模型系列、贪心解码。暂不实现训练、量化、分布式服务和完整 OpenAI API。模型系列、规模、精度和上下文上限在硬件信息确认后锁定。

## 当前证据

- 用户提供的远程环境：torch 2.6.0+cu124、transformers 4.52.4、triton 3.2.0。
- 安装路径指向 Python 3.10 环境，实际解释器版本待采集。
- 用户拥有远程 Linux 多卡服务器，有推理或 CUDA 经验，预计投入 4–6 周。
- 硬件：4 × NVIDIA A800-SXM4-80GB，每卡报告 81920 MiB；驱动 550.144.03，nvidia-smi 显示 CUDA 12.4（不代表已安装的 toolkit 版本）。
- 拓扑：任意两卡间显示 NV8；四卡均关联 NUMA 1，CPU affinity 为 32–63,96–127。
- 用户提供的 2026-11-18 快照：GPU 0/1/2/3 分别占用 77933/1/26977/1 MiB。所有卡 GPU-Util 为 0%，进程表为空；不能据此认定设备独占或持续空闲。
- 单卡阶段优先考察 GPU 1 或 3，但运行前需确认可用性。是否共享、可用模型路径仍待确认；不停止现有 GPU 任务。
- 多卡实验在单卡验证后开展，先 2 卡再 4 卡；记录计算时间与通信时间，不能假设线性加速。
- 已安装依赖不等于 GPU 可用或依赖组合已通过验证；保留当前环境，暂不升级。

## 测评协议

- 正确性：使用相同权重、tokenizer、精度、输入 token IDs 和贪心策略，对比参考实现。记录 logits 的最大/平均绝对误差及 token 一致率；容差在精度确定后设定，不能为通过测试随意放宽。
- 工作负载：短输入长输出、长输入短输出、混合长度；分别测单请求和并发扫描。具体长度与并发档位由模型上下文和可用显存确定。
- TTFT：请求提交至首 token 产生，包含队列等待；ITL：同一请求相邻输出 token 的时间间隔。端到端时延：提交至完成。
- 报告时延 P50/P95/P99，并注明样本数；低样本量的尾分位数只作观察。
- 输出吞吐：测量窗口内完成请求的输出 token 总数除以窗口时长；请求吞吐使用相同窗口。明确排除预热，记录实际生成长度与 EOS 策略。
- 显存：同时记录框架 allocated/reserved 峰值与设备显存观察值，不能混用；额外报告 KV Cache 容量和最大可承载并发。
- 性能：固定模型、精度、软件版本、硬件、输入和随机种子；预热、GPU 同步后测量，至少重复 3 次，保存各次结果及波动。profiling 与正式测量分开。
- 对照：首先比较自身基线与单项优化，再组合优化做消融；外部框架比较需披露配置及功能差异。
- 服务目标：获取基线后、优化前锁定 TTFT/ITL 的目标阈值，测量满足阈值的请求吞吐；不预先宣称提升百分比。
- 每次实验记录代码版本或源码快照标识、命令、环境、工作负载、原始数据和结论。共享 GPU 的干扰须披露。
